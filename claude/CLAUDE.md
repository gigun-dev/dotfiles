# グローバル方針(全プロジェクト共通)

## 作業の癖の矯正(cclens 実測 2026-09-04: 996セッション・68プロジェクトで再計測)

- **本番に触るのは、依頼者がその回に明示したときだけ。** deploy / remote への migration /
  本番 DB への書き込みを、コミットや検証の流れで「ついでに」やらない。
  直近90日で 145件が分類器に止められている(それ以前は 6件 = 増えているのはこれだけ)。
  拒否理由はほぼ全部「明示の指示なしにコミットへ連結した本番配備」。
  **1回の承認を次の回へ持ち越さない。**
- **編集前に対象を Read する。** 最多は「まだ読んでいないファイルへの Edit」(255件)で、
  old_string 不一致(72件)ではない。**Edit を書く前に、そのファイルをこのセッションで
  読んだかを思い出す。** 読んでいなければ先に Read。不一致で失敗したときは old_string を
  いじり回さず、再 Read してから直す。
  ⚠️ **subagent に実装を渡すときは、この1行を指示に必ず入れる** — 実装は subagent がやるので、
  ここに書くだけでは届かない(出力トークンの大半が subagent 側)。
- **パスを推測しない。** ls / Glob で実在を確認してから Read/Edit/Bash に渡す。
  (137件 → 直近90日 64件。**規則が効いた数少ない例**)
- **`cd` を繰り返さない。** Bash の25%が単独 cd だった。コマンドは絶対パスで打つ。

## 開発の進め方

- **実装は subagent(implementer / artisan)に委譲し、main は設計・レビューに徹する。**
- **コメントは必要十分に。多いほど良いではない。** 冒頭に「何を守るか・何の事故を止めるか」、
  行には「その行の理由」だけ。ボツ案は再提案されそうなものだけ。訂正は置き換え(旧文は 1 行)。
  (2026-09-04 に「コードと同量レベル」から改めた。cf-fireboard で 45% がコメントになり、
  読むたびに 10 万 token 級を通っていた。) リポジトリに `.claude/rules/comments.md` があればそちらが正。
- **恒久情報は Claude メモリーではなくリポジトリ内ファイルへ**(git 管理・マシン非依存・
  他エージェント可視)。セッション引き継ぎは docs/next-directions.md 方式。
  未導入リポジトリへの導入は `/harness:doctor`(gigun マーケットプレイスの harness プラグイン)。
  doctor は既定では診断のみ、導入・修復は承認を取ってから実行する。
